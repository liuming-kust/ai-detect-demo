## ⚠️ 重要声明
本工具是学术论文的配套实证程序，并非商业AI检测产品。

本工具是论文《数智治理的僭越：AI文本检测的困境与回归》（刘明等，2026）的配套源代码，对应论文第4.3节“跨体裁文本的‘流畅度陷阱’”分析。

本工具不声称能“检测”AI生成文本。它演示的是：在统计范式下，检测为什么行不通。

本工具实际做什么
本工具实现了主流检测器（GPTZero、Turnitin等）所依赖的22项公开统计特征——句法的、词汇的、结构的。它使用固定的、透明的权重，没有数据训练的分类层。

其目的是揭示一个结构性的状况：

在任何固定的、透明的统计框架下，规范性的人类文本与机器生成文本占据重叠的特征空间。

这不是在说“这段文本是AI生成的”。这是在演示：用于检测的统计特征，一旦文本达到一定的流畅度和规整度，就无法区分人类写作和机器写作。

为什么存在多套评分体系？
本工具提供多套预设评分体系（如 long_sentence_heavy、balanced、lexical_focused 等）。同一文本在不同体系下会得到不同的分数。

这不是缺陷，这正是要点。

商用检测器做的也是同样的事——它们选择不同的特征、不同的权重、不同的专有校准。同一篇文本（老舍的《林海》）在不同商用平台上获得的AI分数从0%到99.9%不等。这不是因为文本变了，而是因为检测器的设计变了。

AI分数不是文本的属性。它是检测器设计的属性——其特征选择、权重方案和专有校准的产物。

逻辑：一个归谬实验
本工具建立在归谬法论证之上：

如果一个最小的、透明的特征集——仅使用公开文档中的统计维度，固定权重——已经使规范性人类文本与机器输出产生严重重叠（两者都在约55–60%区间）……

……那么在它之上叠加更多不透明的、数据训练而成的层，无法解决结构性问题，只能掩盖它。

本工具暴露了商用黑箱所隐藏的东西。

商用系统看起来“准确”，不是因为它们解决了重叠，而是因为它们的专有分类层学会了重新解释和压制原始的统计接近度。它们的“精巧”不是范式有效的证据；它是重叠可以被不透明决策边界掩盖的证据。

如何解读你的结果
如果你用本工具检测一篇规范的人类文本，得到一个“高风险”分数：

这并不意味着这段文本是AI生成的。

这意味着，在所有检测器所依赖的统计特征下，你的文本落入了与机器生成文本相同的特征空间。

这种现象在论文中被命名为 “流畅度陷阱”（Fluency Trap） ：越是规范流畅的人类文本，越容易被标记为AI生成。

如果你在不同评分体系间切换，观察到分数显著变化，这本身就是一个发现：分数是检测器设计的函数，而非文本的内在属性。

## 功能概述
提取文本的22维统计特征（句法复杂度、词汇多样性、篇章结构、AI特征、补充统计）

支持多套预设评分体系 + 自定义权重调节

提供可视化分析报告（雷达图、句子分布图等）

支持文件上传（.txt/.docx/.pdf）

快速开始
